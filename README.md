# Boop 文本处理工具

> 灵感来自 macOS 原生应用 [Boop](https://github.com/IvanMathy/Boop)，一个强大的文本处理工具。

## 📦 项目说明

本项目包含 Boop 的多个实现版本，分别位于不同的子目录中：

| 版本 | 目录 | 技术栈 | 状态 | 特点 |
|------|------|--------|------|------|
| **Python 版** | [`boop/`](boop/) | Python + Tkinter | ✅ 稳定可用 | 功能完整，开箱即用 |
| **Rust 版** | [`boop-rust/`](boop-rust/) | Rust + egui | 🚧 开发中 | 高性能，体积小，现代化 |

---

## 🎯 为什么进行技术迁移？

原始的 Python + Tkinter 版本虽然功能完善且跨平台，但在实际使用中存在一些难以避免的局限性：

### 当前版本的瓶颈

| 瓶颈 | 影响 | 具体表现 |
|------|------|----------|
| **资源占用大** | 内存消耗高 | Python 运行时 + Tkinter 约占用 ~100MB 内存 |
| **分发体积大** | 下载和安装慢 | 打包后的应用体积约 50-80MB（含 Python 运行时） |
| **启动速度慢** | 用户体验差 | 冷启动需要 1-2 秒（加载 Python 解释器和依赖） |
| **UI 能力有限** | 交互体验不足 | Tkinter 的渲染能力和现代化 UI 表现不足 |
| **并发受限** | 脚本执行效率低 | Python GIL 限制了真正的并行处理能力 |
| **类型安全弱** | 运行时错误多 | 动态类型导致运行时才能发现部分错误 |

### 迁移目标

通过技术栈升级，实现以下目标：

- ✅ **体积减少 85%**：从 50-80MB 降至 6-9MB
- ✅ **内存减少 70%**：从 ~100MB 降至 ~30MB
- ✅ **启动速度提升 4x**：从 1-2 秒降至 0.2-0.5 秒
- ✅ **更好的 UI 体验**：即时渲染、现代化界面、流畅动画
- ✅ **真正的并发能力**：基于 tokio 异步运行时，并行执行脚本
- ✅ **类型安全**：编译期检查，减少运行时错误和崩溃

## ⚖️ 技术选型对比

在确定迁移方向时，我们全面对比了 **Rust** 和 **Go** 两种主流系统级语言。

### 语言特性对比

| 维度 | Rust | Go | Python (当前) |
|------|------|----|---------------|
| **二进制体积** | 3-10 MB | 10-25 MB | 50-80 MB (含运行时) |
| **内存占用** | ~30 MB | ~50 MB | ~100 MB |
| **启动速度** | 0.2-0.5 秒 | 0.3-0.8 秒 | 1-2 秒 |
| **运行性能** | ⭐⭐⭐⭐⭐ 极高 | ⭐⭐⭐⭐ 高 | ⭐⭐ 一般 |
| **开发效率** | ⭐⭐⭐ 中等 | ⭐⭐⭐⭐⭐ 极高 | ⭐⭐⭐⭐⭐ 极高 |
| **学习曲线** | 陡峭 | 平缓 | 平缓 |
| **内存安全** | ✅ 编译期保证 | ⚠️ 运行时 GC | ⚠️ 运行时 GC |
| **并发模型** | async/await | goroutine | threading (GIL) |
| **GUI 生态** | egui (成熟) | Fyne (基础) | Tkinter (基础) |

### GUI 框架对比

| 框架 | 语言 | 渲染模式 | 跨平台 | 成熟度 | 编辑器支持 | 适用性 |
|------|------|---------|--------|--------|-----------|--------|
| **egui** | Rust | 即时模式 | ✅ 优秀 | ⭐⭐⭐⭐⭐ | ✅ 内置 CodeEditor | ⭐⭐⭐⭐⭐ |
| **Fyne** | Go | 即时模式 | ✅ 良好 | ⭐⭐⭐⭐ | ⚠️ 基础 TextWidget | ⭐⭐⭐⭐ |
| **iced** | Rust | 保留模式 | ✅ 良好 | ⭐⭐⭐⭐ | ⚠️ 需自定义 | ⭐⭐⭐⭐ |
| **Gio** | Go | 即时模式 | ✅ 良好 | ⭐⭐⭐ | ❌ 需手写 | ⭐⭐⭐ |
| **Tkinter** | Python | 保留模式 | ✅ 良好 | ⭐⭐⭐⭐ | ⚠️ 基础 Text | ⭐⭐⭐ |
| **gtk-rs** | Rust | 保留模式 | ⚠️ 需依赖 | ⭐⭐⭐⭐ | ✅ 完整 | ⭐⭐⭐ |

**选择 egui 的原因：**
- ✅ **纯 Rust 实现**，无系统依赖，编译简单
- ✅ **即时模式渲染**，UI 响应更快，无状态同步问题
- ✅ **跨平台一致**，macOS/Windows/Linux 表现统一
- ✅ **内置 CodeEditor**，减少开发工作量
- ✅ **活跃社区**，持续更新，文档完善

### Go 方案的详细分析

#### Go 的优势
- ✅ **开发效率极高**：语法简洁，编译极快
- ✅ **天然并发**：goroutine + channel 模型优雅
- ✅ **标准库完善**：网络、文件、JSON 等开箱即用

#### Go 的劣势（在此项目中）
- ❌ **GUI 生态不成熟**：Fyne 组件库有限，编辑器功能弱
- ❌ **GC 开销**：垃圾回收带来不可预测的暂停
- ❌ **二进制体积大**：内置运行时导致体积通常 >10MB
- ❌ **内存占用高**：GC 需要额外内存 overhead
- ❌ **UI 定制困难**：不如 egui 灵活

### 最终选择：Rust + egui

**决策因素：**

1. **GUI 框架成熟度**：egui 在跨平台即时模式 GUI 方面明显领先
2. **资源效率**：二进制体积和内存占用符合优化目标
3. **用户体验**：即时渲染提供更流畅的交互体验
4. **长期维护**：类型安全减少 bug，编译期检查保障质量
5. **生态完善度**：tokio + serde + tracing 生态成熟

> **结论**：虽然 Go 开发效率更高，但对于桌面 GUI 应用，Rust + egui 在用户体验和资源效率上更有优势。

## 🔧 脚本系统方案对比

Boop 的核心是 Python 脚本系统，我们对比了三种执行方案：

### 方案对比矩阵

| 维度 | 方案A: pyo3 嵌入 | 方案B: WASM 插件 | 方案C: 子进程 (采用) |
|------|-----------------|-----------------|-------------------|
| **脚本兼容性** | ✅ 100% 兼容 | ❌ 需重写 | ✅ 100% 兼容 |
| **执行性能** | ⭐⭐⭐⭐ 快 | ⭐⭐⭐⭐⭐ 极快 | ⭐⭐⭐ 中等 |
| **内存占用** | 高 (+15MB) | 低 (+2MB) | 低 (按需) |
| **二进制体积** | +30MB | +5MB | 无影响 |
| **包管理** | ✅ 支持 pip | ❌ 不支持 | ✅ 支持 pip |
| **沙箱安全** | ⚠️ 有限 | ✅ 完全隔离 | ✅ 进程隔离 |
| **并发执行** | ⚠️ GIL 限制 | ✅ 真正并行 | ✅ 进程并行 |
| **崩溃隔离** | ❌ 影响主程序 | ✅ 完全隔离 | ✅ 完全隔离 |
| **开发门槛** | 中 | 高 | 低 |
| **调试体验** | ✅ 可用 Python 调试 | ⚠️ 复杂 | ✅ 标准调试 |

### 最终选择：子进程方案（方案 C）

**选择理由：**

1. **完全兼容**：现有 Python 脚本无需任何修改
2. **进程隔离**：脚本崩溃不会影响主程序稳定性
3. **包管理简单**：用户可自行 `pip install` 依赖
4. **体积极小**：不嵌入 Python 运行时，保持 6-9MB
5. **安全性好**：可设置超时、资源限制

**性能影响：**
- 每次执行脚本需启动新进程（~100-300ms 开销）
- 对于文本处理脚本，这个开销可接受
- 未来可优化为进程池复用

## 🎨 UI 组件能力对比

### Tkinter vs egui 平替分析

| Boop UI 组件 | Tkinter 实现 | egui 替代方案 | 平替难度 | 代码量变化 |
|-------------|-------------|--------------|---------|-----------|
| **主窗口** | `tk.Tk()` | `eframe::Frame` | ✅ 完全替代 | -40% |
| **菜单栏** | `tk.Menu` | `egui::menu::bar` | ✅ 完全替代 | -50% |
| **文本编辑器** | `tk.Text` | `egui::TextEdit` | ⚠️ 部分功能需手写 | +25% |
| **行号显示** | 独立 `Text` | 自定义绘制 | ⚠️ 需自行实现 | 新增 ~200 行 |
| **撤销/重做** | 自定义历史栈 | 同左 | ✅ 逻辑可复用 | 相同 |
| **多光标编辑** | 自定义实现 | 需完全重写 | ⚠️ 复杂度高 | 后续实现 |
| **脚本选择器** | `ttk.Treeview` | `ScrollArea` + 循环 | ✅ 完全替代 | -33% |
| **搜索防抖** | `after()` 定时器 | `request_repaint_after` | ✅ 更优雅 | -50% |
| **首选项面板** | `ttk.Notebook` | `egui::Tabs` | ✅ 完全替代 | -17% |
| **状态栏** | `tk.Frame` | `TopBottomPanel` | ✅ 完全替代 | -30% |
| **弹窗/对话框** | `tk.Toplevel` | `egui::Window` | ✅ 更简洁 | -40% |

**总体评估：**
- ✅ **核心组件**：100% 可平替，代码更简洁
- ⚠️ **高级功能**：多光标需重写，但逻辑可复用
- ✅ **开发体验**：egui API 更现代，声明式 UI
- ✅ **整体代码量**：预计减少 17-20%

## 🚀 快速开始

### Python 版本（稳定版）

适合不想折腾环境，直接使用的用户：

```bash
cd boop
pip install -r requirements.txt
python3 -m boop
```

详细使用说明请查看 [boop/USER_GUIDE.md](boop/USER_GUIDE.md)

### Rust 版本（开发中）

适合追求性能，愿意尝试新技术的用户：

#### 环境要求
- Rust 1.70+（[安装指南](https://www.rust-lang.org/tools/install)）
- Python 3.9+（用于执行脚本）

#### 编译和运行

```bash
cd boop-rust

# 开发模式（快速迭代）
cargo run

# 发布模式（优化性能）
cargo run --release

# 运行测试
cargo test

# 代码检查
cargo clippy
```

#### 打包分发

```bash
# macOS
./build.sh
# 输出：target/release/Boop.dmg

# Windows/Linux
cargo build --release
# 手动打包或使用 cargo-bundle
```

> ⚠️ Rust 版本仍在开发中，核心 UI 已实现，部分高级功能待完善。

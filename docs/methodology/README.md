# 架构文档方法论

本目录汇集了用于撰写 Boop 项目架构与业务文档的通用参考资料。它源自项目的架构文档生成实践（C4 模型 + ADR + Python 工程特性分析），整理为独立于任何特定工具链的通用写作指南。

## 文档清单

| 文档 | 说明 |
|------|------|
| [C4 模型参考](./c4-reference.md) | C4 四个层级的定义、图例、Python 项目中的自然映射、Mermaid 配色规则 |
| [ADR 模板](./adr-template.md) | 架构决策记录模板 + 命名规范 + 状态语义 + 索引格式 |
| [Python 模式检测清单](./python-patterns.md) | 14 项 Python 工程维度（打包、依赖、类型、异步、数据层、CLI、配置、测试、质量、部署、安全等）的检测标记清单 |
| [输出模板](./output-templates.md) | 业务概览 / 模块映射 / 数据流 / 入职指南四种架构文档的标准输出模板 |

## 使用方式

### 为现有项目补充架构文档

1. 先用文件系统勘察项目（Glob 找 `pyproject.toml`、`setup.py`、`requirements.txt`、`Dockerfile`、`tox.ini` 等标记文件）。
2. 按 [Python 模式检测清单](./python-patterns.md) 逐项打勾，给出每项的"现状 → 证据 → 评估 → 建议"四列式结论。
3. 按 [C4 模型参考](./c4-reference.md) 绘制 L1/L2/L3 图（L4 仅在必要时）。
4. 按 [输出模板](./output-templates.md) 写出概览、模块映射、数据流、入职指南。
5. 用 [ADR 模板](./adr-template.md) 把关键决策（框架选型、依赖管理方案、项目布局）单独记录。

### 为新项目建立文档基线

在项目初始化后、首行代码前，先写 3-5 份 ADR 把选型拍板，再按上面的流程产出架构文档。

## 文档处理原则（项目约定）

1. **证据驱动**：每个架构论断必须引用文件，否则标注为推断。
2. **单一事实源**：同一事实出现在多处时，保留在最具体的文档中，其他位置改为链接。
3. **不删除既有内容**：被取代的小节用 `> [OUTDATED — superseded by <link> on YYYY-MM-DD]` 标注。
4. **结构化分组**：配置表、属性表按功能分区，不要堆成一大块。
